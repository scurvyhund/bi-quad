mod_obstruct.c — Debug Session Reference
=========================================
Date: 2026-04-09
Topic: is_valid_ending bitset bug + fix + test instrumentation plan


THE BUG
-------
Phase 1 of main() marks endings in the is_valid_ending bitset purely
because 2n²+2n+1 ≡ e (mod 10^k) for some n.  It does NOT filter out
e values whose last digit is 5.  Since 2n²+2n+1 is always odd, a last
digit of 5 means the number is divisible by 5 — composite, never prime.
These dirty endings propagate into valid_firsts (via reverse_k) and then
into the Hensel lifting stage, causing spurious survivors and potentially
masking real obstructions.


IMPACT ON RESULTS
-----------------
- Obstructions already printed are VALID (dirt only inflates, never deflates).
- Survivor counts are inflated — some d values that should show 0 survivors
  (a real obstruction) may have shown nonzero.  Those obstructions are missed.
- Estimated ~15-25% excess work in Phase 3 / Hensel lifting from dirty entries.
- For a mathematical proof, a clean restart is required.

THE FIX — Phase 1 loop in main()
---------------------------------
Current code (around line 309):

    for (long n = 0; n < mod; n++) {
        long e = ending_for_residue(n, mod);
        if (!BITSET_GET(is_valid_ending, e)) {
            BITSET_SET(is_valid_ending, e);
            num_endings++;
        }
    }

Fixed code — add digit filter before setting bit:

    for (long n = 0; n < mod; n++) {
        long e = ending_for_residue(n, mod);
        long last_digit = e % 10;
        /* 2n²+2n+1 always odd; last digit 5 → div by 5 → composite */
        if (last_digit == 5 || last_digit == 0)
            continue;
        if (!BITSET_GET(is_valid_ending, e)) {
            BITSET_SET(is_valid_ending, e);
            num_endings++;
        }
    }

MATHEMATICAL NOTE
-----------------
2n²+2n+1 mod 10 can ONLY produce {1, 3, 5}.  (Not 7, not 9 — ever.)
Filtering out 5 (divisible by 5 → composite) leaves just {1, 3}.

mod 100 — the six valid last-two-digit patterns after filtering:
  [even][1]:  01, 21, 41, 61, 81
  13:         the only way to get last digit 3

Emirp constraint — reversing those patterns gives valid first-two digits:
  [1][even]:  10, 12, 14, 16, 18
  31:         the reverse of 13

This filter belongs in Phase 1 before any ending is admitted to the bitset.
