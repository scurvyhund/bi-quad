CONTEXT
-------
mod_obstruct.c performs a modular obstruction search for
bi-quadratic emirps (primes p = 2n²+2n+1 where rev(p) is
also of that form). At precision k, it checks all 10^k
residue classes for each digit count d, proving no d-digit
pair can exist when survivors = 0 (obstruction).

The k=10 run was launched to independently verify cvpipe
pipeline results and push obstruction coverage further.

WHY d=21 IS SLOW
----------------
At k=10, mod = 10^10 (10 billion residues per d value).
For small d (e.g., d=11), the range [10^10, 10^11-1] is
small relative to mod, so 99.999% of residues have no
representatives and skip instantly.

For d=21, the range [10^20, 10^21-1] contains ~9×10^10
values per residue class. Virtually no residues skip.
All 10 billion must go through the full computation:
GMP big-number arithmetic, binary search over ~1 billion
valid_firsts, and Hensel lifting for q-side verification.

Previous d values with obstructions or few survivors
computed fast because most residues failed early filter
checks. d=21 is at the saturation boundary where most
residues pass all filters.
