 Tools: hunt.c (emirps, GMP) | palhunt_gmp.c (prime palindromes, GMP)

--- 1. CLONE / SYNC THE REPO ------------------------------------------------
# fresh clone (either remote; master_dev is the active line)
git clone git@gitlab.com:scurvyhund/bi-quad.git
git clone git@codeberg.org:scurvyhund/bi-quad.git
# update an existing clone to the active line  (DISCARDS local edits)
git fetch origin && git checkout master_dev \
  && git reset --hard origin/master_dev
# update but KEEP local edits
git stash && git pull && git stash pop
# revert one botched file to the committed version
git checkout -- <file>

--- 2. INSTALL DEPS ---------------------------------------------------------
# nitroII  (Debian / BunsenLabs)
sudo apt install -y build-essential libgmp-dev git lm-sensors
# nitroIII (Fedora)
sudo dnf install -y gcc gmp-devel make git lm_sensors

--- 3. BUILD ----------------------------------------------------------------
# GOTCHA: -o names the BINARY, the .c source comes LAST.
#   right: gcc ... -o palhunt_gmp palhunt_gmp.c -lgmp
#   wrong: gcc ... -o palhunt_gmp.c -lgmp      (clobbers source, no main)
# palindrome hunter  (-march=native auto-tailors to the local CPU)
gcc -O3 -march=native -mtune=native -std=c99 -fopenmp \
  -o palhunt_gmp palhunt_gmp.c -lgmp
# emirp hunter
gcc -O3 -march=native -std=c99 -fopenmp -o hunt hunt.c -lgmp
#   (nitroIII production CPU flag instead of native: -march=znver2)
# modular sieve (uses the Makefile's znver2 CFLAGS)
make

--- 4. SANITY CHECK (always run before a long job) --------------------------
# palindrome build is good if this prints 181, 313 (d=3) and 3187813 (d=7)
./palhunt_gmp 1 7
# emirp build quick check (d=5 must report the emirp 12641<->14621)
./hunt 5 7

--- 5. LAUNCH A LONG RUN (survives logout via nohup) ------------------------
mkdir -p logs
# emirp hunt, one digit-length d (stdout=hits, stderr=progress)
nohup ./hunt 26 26 > logs/hunt_d26.log 2>logs/hunt_d26.stderr &
echo "PID $!"
# d=27 run (launched 2026-06-28; est. ~9 days; auto-resumes from
# hunt_d27.ckpt if present — just re-run the same command)
nohup ./hunt 27 27 > logs/hunt_d27.log 2>logs/hunt_d27.stderr &
echo "PID $!"
# palindrome hunt, a digit range. NOTE: even d = 0 (palindrome /11), so
# only ODD d are genuine tests -> run them one at a time, e.g. d=27:
nohup ./palhunt_gmp 27 27 > logs/palhunt_d27.log 2>&1 &
echo "PID $!"

--- 6. WATCH / CHECK A RUNNING JOB ------------------------------------------
ps -o pid,etime,pcpu -p <PID>        # one process by PID
ps -o pid,etime,pcpu,args -C hunt    # all 'hunt' processes
pgrep -af palhunt_gmp                # find palhunt by name + args
cat   logs/hunt_d26.log              # full log
tail -3 logs/palhunt_d27.log         # last few lines
uptime                               # load average
free -h                              # RAM / swap (swap use => thrash!)
sensors 2>/dev/null | grep -iE 'Tdie|Tctl|Core 0'   # CPU temp
# VERIFY a completed run's "prime-eligible" / palindrome candidates.
# hunt.c "prime-eligible" and "palindrome" = passed the composite SIEVE
# only, NOT proven prime. Before claiming a prime palindrome (or emirp),
# factor each candidate p independently:
factor <p>                           # GNU factor: definitive (full facts)
# for 27+ digit p, GNU factor can be slow on a large prime factor; a
# quadratic sieve settles composites fast. We use Michel Leonard's qs:
#   https://github.com/michel-leonard/C-Quadratic-Sieve  (public domain)
# A single proper factor => composite => NOT a prime palindrome, and the
# factors are a self-checkable certificate (factor1*factor2 == p). See
# CREDITS.md. (d=27: all 3 palindrome candidates in pals.txt composite
# by qs, 2026-07-05.)

--- 7. THROTTLE / STOP A JOB ------------------------------------------------
nice -n 19 ./hunt 19 21              # start at lowest priority
taskset -c 0-6 ./palhunt_gmp 27 27  # pin to 7 of 8 cores (runs cooler)
renice 19 -p <PID>                   # lower priority of a running job
pkill -f palhunt_gmp                 # stop palhunt by name
kill <PID>                           # stop one process by PID

--- 8. COMMIT & PUSH TO ALL THREE MIRRORS -----------------------------------
git status
git add <files>
git commit -m "message"
git push origin   master_dev      # GitLab
git push codeberg master_dev      # Codeberg
git push github   master_dev      # GitHub
git log --oneline -5

--- 9. nitroII DISPLAY: STOP THE SCREEN BLANKING (BunsenLabs / X11) ---------
xset s 1800 1800 && xset dpms 1800 1800 1800   # 30-min idle timeout
xset s off -dpms                               # never blank (no OSD popups)
xset s on +dpms                                # restore default
xset q | grep -iA2 -e 'Screen Saver' -e DPMS   # check current settings
echo 'xset s off -dpms' >> ~/.config/openbox/autostart   # make it persist

--- 10. ZIG (experimental — see docs/zig_experiment_2026-06-06.md) -----------
# install (Fedora): pulls libomp as a dep. 0.14.x keeps @cImport (simplest).
sudo dnf install -y zig          # nitroIII; 0.14.1. (apt: 'zig' on Debian too)
zig version
# use zig as a drop-in C compiler (zero Zig learned, good first taste):
zig cc -O3 -mcpu=znver2 -std=c99 hunt.c -o hunt -lgmp
# build a Zig program that calls GMP (native u128, std.Thread; no OpenMP):
zig build-exe palhunt_gmp.zig -O ReleaseFast -lc -lgmp -mcpu=znver2 \
  -femit-bin=palhunt_zig
# which __udivti3 (etc.) a binary uses — IN binary (compiler-rt) vs libgcc:
nm palhunt_zig | grep -i udivti3      # 'W'/'T' = bundled; 'U' = from a .so

--- 11. BENCHMARKING UNDER LOAD (a long hunt owns the cores) -----------------
# pin a test to spare cores so it won't slow the running hunt:
taskset -c 6,7 ./palhunt_c 19 19
# wall-clock is gated by core availability when oversubscribed; measure CPU
# WORK (user+sys) instead — contention-independent, the honest metric:
/usr/bin/time -f "user=%U s sys=%S s real=%e s" ./palhunt_c 19 19
# isolate codegen from scheduling: compare SINGLE-core before multi-core.
taskset -c 7 ./palhunt_c 17 17

--- 12. GITHUB MIRROR — one-time setup (gh CLI) -----------------------------
sudo dnf install -y gh             # Fedora; Debian/nitroII: sudo apt install gh
gh auth login                      # GitHub.com -> SSH -> Login with web browser
#   device-code flow is CROSS-MACHINE: copy the one-time code, enter it in ANY
#   browser already logged into the account (e.g. a second box), then the CLI
#   completes. SSH choice auto-uploads ~/.ssh/id_ed25519.pub to the account.
gh auth status                     # confirm: 'Logged in ... (ssh)'
gh repo create scurvyhund/bi-quad --source=. --public --push --remote=github \
  --description "..."              # creates repo, adds 'github' remote, pushes
gh repo edit scurvyhund/bi-quad --add-topic number-theory --add-topic emirp \
  --add-topic palindrome ...       # (repeat --add-topic for each)
gh repo view --web                 # open it in a browser

--- 13. VALIDATE / A-B BENCHMARK / TIMING FORENSICS -------------------------
# palindrome-first cross-check of hunt.c (independent method; agree = truth):
python3 palfirst.py 1 15
# A/B a hunt.c optimization: build the PRE-opt source from git, race both
# (same flags, singleton). 7dd367e added the skip-opt; a974123 is pre-opt:
git show a974123:hunt.c > /tmp/hunt_noopt.c
gcc -O3 -march=native -std=c99 -Wall -fopenmp -o /tmp/hunt_noopt \
  /tmp/hunt_noopt.c -lgmp
/usr/bin/time -v ./hunt 23 23 ; /usr/bin/time -v /tmp/hunt_noopt 23 23
#   NOTE: the skip-opt is LOSSY (drops div-5) -- counts differ by design;
#   compare EMIRPS / prime-eligible (opt-invariant), not raw/palindromes.
# per-block rate profile of a checkpoint log (spot contention vs clean run):
python3 ~/programming/python_gold/rate_profile.py logs/hunt_d27.stderr
#   corr(rate,progress)~0 => flat/clean; big spread => contended/throttled.

--- 14. PALINDROME COMPOSITENESS CERTIFICATES (qs) --------------------------
# A palindrome hunt only flags candidates; PROVE each prime-eligible one
# composite before claiming the conjecture holds at a new d. Two steps:
# (1) quick verdict, (2) self-checkable factorization certificate.
# quick deterministic verdict (valid < 3.317e24, i.e. through d=24 fully
# and most of d=25; above that it is strong-probabilistic, so still factor):
python3 ~/programming/python_gold/miller_rabin.py 1427056470511150746507241
# factor a prime-eligible palindrome (Michel Leonard's qs; ~mins at d=25):
qs 3153012324698964232103513          # -> 89 * 14127161 * 2507729951679497
# certify the factorization (re-multiplies; no trust in qs required):
python3 ~/programming/python_gold/verify_factors.py \
  "3153012324698964232103513 = 89 * 14127161 * 2507729951679497"
#   div-5 palindromes (p ends in 5) are trivially composite -- skip qs.
#   Record results in pals_d<dd>.txt (see pals.txt / pals_d25.txt style).

 Notes:
 - Cumulative candidates through digit-length d  ~=  n_max(d) ~= sqrt(10^d / 2).
 - 'survivors(raw)' includes palindromes; 'EMIRPS'/'CON-VERSE' = the real
   bi-quadratic emirp count. hunt.c is the trustworthy ground truth.
 - A long run that makes the box unusable = MEMORY thrash (swap), not CPU.
   Watch 'free -h'; hunt.c uses ~3 MB, mod_obstruct can be large at high k.
 - hunt.c skip-value opt (2026-06-29): n%10 in {1,3,6,8} -> p ends in 5
   (composite); skipped before any GMP work via VALID_NMOD[] table. Saves
   ~40% of iterations (~35% wall-clock). Validated d=5..19 vs landscape.
