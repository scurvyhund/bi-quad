# Bounds audit — 2026-11

A per-tool audit for one question:
**can this tool silently give a wrong answer at the inputs it has been run on?**
"Silently" is the point.
A crash is cheap; a plausible wrong number with exit status 0 is not.

Started 2026-11-19, after two new standing rules
(global `CLAUDE.md`: *Width budget* and *Fixed-size arrays*)
and the observation that `hunt.c`, the ground-truth brute force, still had three faults.

## Method — edges first, reading second

The 2026-09-04 audit (`session_2026-09-04_audit.md`) was read-first,
because a live run forbade rebuilding.
It found only the classes it looked for, and its Finding 1 was argued "latent" but never run.
This audit runs things first. For each tool:

1. Inventory every fixed-width value: `long long`, `u64`/`u128`, every narrowing out of an `mpz_t`, every fixed array and `MAX_*`.
2. State the **width ceiling** (see `GLOSSARY.md`) from the widest intermediate; run at it and one past it.
3. Degenerate and bad-argument shapes: junk, `d <= 0`, `d = 1`, smallest `k`, reversed ranges.
4. clang `-fsanitize=address,undefined,signed-integer-overflow,unsigned-integer-overflow`, plus Valgrind.
   (gcc cannot do the unsigned check, and on this box lacks `libasan`/`libubsan` entirely.)
5. Known answer per mode; output diffed against the pre-change binary.
   **Sort the hit lines first for threaded tools** — under `schedule(dynamic)` hit order varies run to run.
6. Checkpoint tools: valid resume, mismatched file, malformed file.

A new test must be shown to fail — on the old code, or under a mutation.

## Findings

### Fixed

- **`hunt`: no argument validation** — `./hunt 0 0`, `-3 -3`, `abc 2` dumped core on SIGFPE.
  `(unsigned long)(d-1)` wraps at d = 0. `5f5fc4f`.
- **`hunt`: checkpoint keyed by d alone** — `hunt` and `hunt_noopt` (different filters, different counts) shared `hunt_d<NN>.ckpt` and could resume from each other.
  Rejection was silent, and write failures were unchecked. `7b25e88`.
- **`m_at`: `(u128)(b * b)`** squared in `int64` before widening — UB and a wrong band edge for |B| > 3.04e9.
  The new test fails on the old header. `c014ae4`.
- **`palcurve`: negative B or C → silently wrong search.**
  **This closes 2026-09-04 Finding 1**, which sat open as "latent" for 2.5 months and had never been run.
  Run now on `2m²−2m+1`, our own curve shifted by m = n+1: d = 7 found **1 of 3** palindromes (`3187813` missed), d = 13 found **0 of 2**, each a clean exit.
  No published result is affected — all 13 curves in `curve_palindromes.txt` have small positive B, C. `dd8d550`.
- **`compute_n_bounds(d < 1)`** now refuses in the header (backstop for every caller). `9c6d43b`.
- **Test noise** — two deliberate wraps in the tests made a clean tree print sanitizer errors. `35d6942`.

- **`mod_obstruct`: Hensel lift overflowed int64 at k ≥ 10 and silently capped at 4096 solutions — a FALSE OBSTRUCTION was published and retracted for the wrong reason.**
  `solve_residues` formed `2r²+2r+1` in `long long` (overflow once r > ~2³¹: the last lift at k=10, every lift past it) and dropped solutions past `MAX_HENSEL_SOLS = 4096` (k=9 has endings with 5000).
  Both only *drop* m-residues, so both can only produce false obstructions.
  Against an exact u128 reference (20,000 real endings per k): k=6 0 wrong, k=9 34, k=10 and k=11 **all 20,000**.
  **All 6 of 6** prime-eligible d=21 survivors (`hunt`) lose their own m-residue at k=10 — the full cause of `landscape_k10.log`'s "d=21 OBSTRUCTION" (2026-06-04 08:57).
  The 2026-06-05 retraction blamed the `range<mod` cliff; that is the wrong mechanism (the cliff bug over-counts and cannot produce zero) and the false run came 11 h *after* the cliff fix `22a7121`.
  The `__uint128_t` "fix 091575b" recorded in session memory does not exist in any ref.
  Fixed `417ca34`: exact u128 lift; capacity is the proven bound `hensel_cap(k) = 4·max(2·5^⌊(k−1)/2⌋, 5^⌊k/2⌋)` (tight, attained k=2..12), overflow fatal.
  **Positive control:** fixed binary, k=10 d=21 → **survivors = 8** (38.6 min).
  *Impact:* no currently-cited result depends on it — the emirp bound rests on `hunt`, the palindrome bound on `palhunt_gmp`. Every pre-fix k=9 / k=10 obstruction other than d=21 (k=9: 16, 18, 19; k=10: 18, 19, 20) is confirmed by `hunt`'s prime-eligible = 0. README's "d ≤ 21 via the modular sieve" withdrawn.
- **`mod_obstruct`: `k = 0` made a false `d = 1 OBSTRUCTION`** (mod = 1 → every ending 0 → all filtered; p = 1 is a real survivor), plus a contradictory "saturated" since `sat_level = 0`.
  No argument validation at all: `max_d` 0 / −5 / `x` silently exit 0; k = −1 crashed.
  Fixed `18ed104` (strict parse, ranges, out-of-range checkpoint rejected loudly, honest tested-d count).

- **`mod_obstruct`: one run's checkpoint could hijack another.** Keyed by (max_d, max_k) only, and written even by runs with explicit start arguments.
  The repo's `mod_obstruct.ckpt` (`50 6 6 16`, left by an interrupted k=6 sanity run) made a plain `./mod_obstruct 50 6` start at k=6 d=16, **skipping k=3..5 and d=7..15**, with only a banner note. Mismatches were ignored silently; writes unchecked.
  Fixed: one checkpoint per invocation, build-tagged, rejected loudly. The k=6 sanity test must now run in a fresh directory (it never terminates, so it always leaves a checkpoint that would resume it) — `CLAUDE.md` updated.

- **`palsplit`: a typo'd flag silently changed the count basis.** `21 5 --keep` ran without `--keep5` and exited 0; `-5`, `x`, `0` and a second t were coerced. d = 1 was refused by an unsatisfiable message. Fixed; output byte-identical on 178 + 134 configurations.
  Its arithmetic held at every edge: default mode equals a fresh `hunt` run palindrome-for-palindrome at every d = 1..21; t-independent at every odd d to 37.
  `pals_d15.txt` / `pals_d21.txt` each omit one div-5 value — **documented** (`palindrome_split_search.md` §5), not a defect.

#### `mod_obstruct` full pass (2026-11-19)

- **Phase 3 is sound — traced by hand.** For a true prime-eligible pair (p from n, q = rev(p) from m): `first_n_with_residue` reaches n; `q_first = reverse_k(p_ending)` is exactly q's first k digits (lead digit = p's last digit, 1 or 3, never 0); `valid_firsts` membership ⟺ `reverse_k(f)` is a valid ending, because `reverse_k` is an involution on k-digit strings whose last digit is non-zero, which every valid ending has; `q_ending = reverse_k(f)` is q mod 10^k; `solve_residues` (exact since `417ca34`) returns m mod 10^k; m ∈ [n_min, n_max] since q has d digits. So every such pair — palindromes included — yields a survivor.
- **Soundness sweep, fixed binary, k = 3..9 vs `hunt` prime-eligible** (fresh `hunt 1 21`): 69 (k, d) pairs, **25 OBSTRUCTION claims, all confirmed** (`hunt` = 0), **zero false obstructions**.
- **Exact wherever d ≤ 2k:** survivors = `hunt` prime-eligible in **all 43** such cases (e.g. k = 9, d = 13..18: 4, 6, 5, 0, 1, 0). Past 2k it over-counts, as designed, never to zero.
- **"Saturated ⇒ all larger d saturate" is a TREND, not proven.** Held in every case evaluated — the next 8 d after the first saturation at each k = 1..4 (31 cases; k = 4 d = 22 timed out, not a counter-example). It cannot create a false obstruction, but the "skipped — saturated" line asserts d values never computed.
- Widths of `ending_for_residue`, `reverse_k`, `compute_first_k`, `first_n_with_residue`, the binary search: no faults. Mod-11 even-d diagnostic correctly limited to d ≤ 2k and reads the surviving n.
- **Heartbeat data race — fixed `8c6ddbf`.** `hb_last` was read outside the `(hb)` critical section and written inside it. Now an atomic read / atomic write. TSan did **not** report it (below); the fix rests on the language rules.

#### ThreadSanitizer pass (2026-11-19)

- **Detector validated first.** clang 22 `-fsanitize=thread` + Archer (`OMP_TOOL_LIBRARIES=…/libarcher.so`). **`TSAN_OPTIONS=ignore_noninstrumented_modules=1` is required**: without it a correct program gets 2 false reports from the OpenMP runtime. With it: 0 reports on correct atomic / critical / reduction code; a deliberate race reported at its exact line.
- **9 runs, 0 reports:** `hunt 1 13` (small blocks → checkpoint between regions), `mod_obstruct` k=6 and k=7, `palsplit` 21 `--keep5` and 29 t=8, `palcurve` 2 2 1 21, `palbrute` 15 / 13 `--all` / 13 `--verify`. All binaries confirmed instrumented.
- **`mod_obstruct` heartbeat path:** the short runs never reached it (each d < 20 s — the heartbeat clock restarts per d). k=9 d=19 did (13 heartbeats): still 0 reports for a race that exists by the language rules. **A clean TSan run is evidence about what executed, not proof of race-freedom.**
- **Static review backs it:** every shared write in `hunt`, `palsplit`, `palcurve`, `palbrute` is atomic, in a critical section, or between parallel regions; none has an unlocked read of a variable another thread writes.
